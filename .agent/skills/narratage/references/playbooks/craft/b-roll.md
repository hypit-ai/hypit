# B-roll craft

- Choose the narrative scene before writing prompts. A useful product arc is **problem → failed
  effort → product/mechanism → payoff**, but use the number of beats the story needs.
- Design each shot as a paired package: the image prompt establishes every visible fact; the video
  prompt adds only motion over those facts. Audit every noun and relationship in the video prompt
  against its image prompt.
- Adjacent shots must carry different information. Change location, camera relation, action, prop
  relation, or emotional state; do not make cosmetic crops.
- B-roll is silent. Put narration, music, and effects on explicit audio components.
- Clamp generated shots to 4–15 seconds. Longer material becomes continuous parts sharing one image.
- For software demos, use complementary context and proof images: person/device relationship first,
  then a device-screen shot from a physically possible reverse viewpoint. Use real supplied UI when
  exact fidelity matters.
- Put changing text, labels, arrows, and cards in `text:Track`/`media-track:Track`. Keep product labels and
  UI text physically attached to the product or screen.
