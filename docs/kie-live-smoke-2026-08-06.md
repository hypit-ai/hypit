# KIE live smoke report — 2026-08-06

This is a deployment observation, not a pricing or model-quality guarantee. No credential, account
balance, task id, temporary upload URL or result URL is recorded here.

## Scope

The smoke suite used the real `@svml/local` Runtime, SQLite Build/Operation stores, filesystem
ArtifactStore, exact author model components and `@svml/provider-kie`. It did not bypass the Runtime
with direct generation requests.

Seven representative text endpoints passed, one per selected model family. One additional GPT
Image 2 image-to-image request used a synthetic 64×64 color image to exercise the real KIE file
upload path without sending user or project content.

## Proven Runtime properties

- A completed Build was rerun from the same SQLite/ArtifactStore root and consumed zero additional
  credits. The same verified Product and content digest were reused.
- Generated bytes were downloaded immediately, media-checked and stored under SHA-256 BlobRefs.
- The image-to-image case proved `BlobRef -> KIE file upload -> temporary URL -> createTask ->
  ArtifactStore`; the temporary URL did not enter the author request or Product identity.
- A transient TLS reset during the read-only credit check was safely retried. The paid createTask
  ambiguity rule was not weakened.
- KIE may return an application rejection inside HTTP 200. The Provider now preserves its business
  `code` and `msg` as a non-retryable submission rejection instead of misclassifying it as an
  ambiguous network outcome.

## Contract corrections discovered live

Gemini Omni rejected the first request before charging because output controls were absent. Its
author contract now requires exact duration, aspect ratio and resolution, and optionally accepts a
bounded seed. Those fields enter the author request digest and are translated by the KIE Provider.

Seedream's documented output format is now explicit author content. The first request happened to
default to JPEG; after `outputFormat: "png"` entered the contract and request digest, the live result
was PNG.

## Downstream media law and implementation

MiniMax H3, Gemini Omni and Grok returned AAC even though these representative author contracts did
not ask for a separate audio Product. Grok also carried an MJPEG cover stream alongside its primary
H.264 stream. The implemented `@svml/media-pipeline` and `@svml/provider-media-local` now:

1. enumerate streams instead of assuming one video stream;
2. select the primary moving visual stream by a declared policy that excludes `attached_pic`;
3. report embedded audio as observed media fact;
4. never infer a `SpeechAudioBasis` merely because a container has audio.

The retained Seedance, MiniMax, Gemini and Grok files were replayed through that parser. All four
selected their H.264 stream; Grok's MJPEG stream remained visible as an unselected attached picture.
See [`media-inspection-and-normalization-v1.md`](./media-inspection-and-normalization-v1.md).

The live suite has not exercised all sixteen exact text/image/frame/reference endpoints. The fake
adversarial suite still covers every adapter shape; further paid endpoint tests remain opt-in.
