# `@hypit/html-program`

Portable, frame-addressed HTML terminal programmes. A programme closes one visual render request into a self-contained
document, usage-scoped Artifacts, explicit Video Source sampling plans and the `prepare()` / `applyFrame(frame)` page
ABI. A Video Source closes its selected stream, Picture interpretation and exact sided Source observation for every
output frame. Local execution may select the prepared-source-frame ABI so decoded bitmaps, rather than browser video
seeking, satisfy those observations. HTML Visuals can join current-frame readiness through
`hypit-frame.detail.waitUntil(promise)`. Timed media enters through compiler-owned Picture inputs. The program
can run on any capture backend that implements its frame interface.

Component and effect packages publish `HtmlVisual` values. The NLE delivery compiler composes those values into one
`HtmlProgram`; browser implementations execute that same programme without learning component identities.
Studio uses `seekFrame(frame, options, signal)` to reuse the mounted document across paused seeks. The executor
selects native video candidates and supplies a URL for exact source frames. The runtime loads the current inputs,
runs the active visuals and acknowledges the frame after paint.

A Video Source may also carry a closed Picture reconstruction plan. The current local implementation supports exact
nearest-frame selection; default sided sampling remains the behavior when no reconstruction is selected.
